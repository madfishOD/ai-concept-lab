# Перший локальний пілот — 2026-09-30

## Статус

Технічний цикл реалізовано й перевірено на цьому ПК: браузер → локальний Qwen → ComfyUI → результат → наступна ітерація. Художню придатність до paintover ще має оцінити артіст. Цей звіт не є затвердженням якості чи стилю.

Обладнання: NVIDIA RTX 5090 Laptop, приблизно 24 GB VRAM; 96 GB RAM.
ComfyUI Portable 0.38.0, Ollama 0.35.0, Qwen3.5:9b; SDXL base 1.0, IP-Adapter Plus SDXL ViT-H.
Версії, джерела, хеші: `runtime-manifest.json`, `models.lock.json`, `requirements.lock.txt`, `comfy-requirements.lock.txt`.

## Виявлені проблеми агента та виправлення

1. Qwen пропонував автоматично визначити маску, хоча цього інструменту немає. Програмна перевірка тепер повертає уточнення до запуску; backend генерації також відхиляє відсутню маску.
2. VLM намагалася перетворити запит анімації/рига на статичний концепт. Додано окрему текстову класифікацію наміру до перегляду зображень. Контрольний запит тепер повертає `unsupported`.
3. Промпт редагування іноді був російською, попри інструкцію англійською; наплічник змішувався зі щитом. Додано словник термінів і перевірку кирилиці з окремим виправленням промпту за оригінальним брифом. Фінальний промпт збережено у `final-edit-plan.json`.

Це докази того, що мала локальна модель потребує програмних обмежень і художнього контролю. Кілька успішних прикладів не доводять надійність на всіх запитах.

## Перевірки

- 13 автоматичних тестів: строгий композит із дірками в масці, збереження alpha оригіналу, порожні/кольорові/прозорі маски, несумісні розміри, padding, валідація входів, передача реальних референсів у граф, відновлення без дублювання невідомого submit.
- У чотирьох реальних редагуваннях **0 змінених пікселів поза маскою**. Для фінального наплічника перевірено 982 962 пікселі поза маскою.
- Повторні HTTP-запити з тим самим request ID повертали той самий job ID, без другої генерації.
- Перевірено браузером: ручний запуск, показ результату, продовження з готового варіанта, завантаження PNG-маски. Помилок у browser console під час перевірки не зафіксовано.
- Контрольні маски створені програмно для технічного тесту; це не артістські затверджені маски.

## Наступна художня сесія

1. Переглянути три концепти й фінальний наплічник; позначити корисність у застосунку.
2. Артіст готує власну маску й проводить кілька правок одного варіанта.
3. Окремо оцінити витрачений час на paintover; економія часу поки не виміряна.
4. Зафіксувати, де саме бракує якості: дотримання брифу, стиль, анатомія, зброя, стики. Потім порівнювати наступний workflow на тих самих завданнях.

Першими кандидатами на вдосконалення є спеціалізований inpainting/image-edit workflow та робота з локальним crop для дрібних деталей. Не вважати поточний SDXL workflow остаточним.
